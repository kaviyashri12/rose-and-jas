📖 RSA Encryption + Digital Signature Workflow

Understanding how secure communication works with RSA

🔄 Complete Communication Flow

👤 Alice (Sender)
Message: "Hello Bob!"
⬇
Step 1: Encryption
Encrypt with Bob's Public Key
Step 2: Signing
Sign with Alice's Private Key
⬇
📦 Send Package
Encrypted Message + Digital Signature
⬇
Step 3: Decryption
Decrypt with Bob's Private Key
Step 4: Verification
Verify with Alice's Public Key
⬇
👤 Bob (Receiver)
"Hello Bob!" ✓ Verified

🔬 Detailed Step-by-Step Process

1
📋 Key Generation

Each user generates a unique key pair:

Public Key (e, n) + Private Key (d, n)
  • Public Key: Shared openly with everyone
  • Private Key: Kept secret by the owner
▼
2
✏️ Message Preparation (Sender Side)

Alice prepares to send a message to Bob:

Original Message: M = "Hello Bob!"
  • Creates hash of message: H = SHA-256(M)
  • Encrypts message: C = Encrypt(M, Bob's Public Key)
  • Signs hash: S = Sign(H, Alice's Private Key)
▼
3
📤 Transmission

Send the package over insecure channel:

Send: (C, S)
  • C = Encrypted Message
  • S = Digital Signature
▼
4
📥 Reception (Receiver Side)

Bob receives and processes the message:

Decrypt: M' = Decrypt(C, Bob's Private Key)
Verify: Valid = Verify(M', S, Alice's Public Key)
  • Decrypts message using his private key
  • Verifies signature using Alice's public key
  • If verification passes → Message is authentic!

🧮 RSA Mathematical Foundation

Key Generation:
1. Choose two large primes: p, q
2. Compute n = p × q
3. Compute φ(n) = (p-1) × (q-1)
4. Choose e such that 1 < e < φ(n) and gcd(e, φ(n)) = 1
5. Compute d such that (d × e) ≡ 1 mod φ(n)

Public Key: (e, n)
Private Key: (d, n)

Encryption: C = M^e mod n
Decryption: M = C^d mod n

🛡️ Security Properties

🔒 Confidentiality

Only the intended recipient can decrypt the message using their private key. Even if intercepted, the message remains unreadable.

✅ Integrity

Any tampering with the message will cause signature verification to fail, alerting the recipient.

🆔 Authentication

The digital signature proves the message came from the claimed sender, as only they have their private key.

🚫 Non-Repudiation

The sender cannot deny sending the message because their unique signature is mathematically linked to them.

🌍 Real-World Applications

🔐 SSL/TLS (HTTPS)

Secure website connections use RSA for initial key exchange and authentication.

📧 Email Encryption

PGP and S/MIME use RSA to secure email communications.

💳 Digital Signatures

Legal documents, software distribution, and financial transactions.

🔑 SSH Authentication

Secure shell uses RSA keys for password-less login.

⭐ Best Practices & Recommendations

  • ✅ Always use key size of at least 2048 bits for production systems
  • ✅ Store private keys in secure, encrypted locations
  • ✅ Never share private keys or transmit them over networks
  • ✅ Use different key pairs for encryption and signing
  • ✅ Regularly rotate keys and revoke compromised ones
  • ✅ Use hardware security modules (HSM) for high-security applications
  • ✅ Combine with other algorithms (AES for bulk encryption, RSA for key exchange)
